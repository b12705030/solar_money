## 地圖互動時的兩階段流程

當使用者移動地圖時，前端以 600ms debounce 觸發：

```
moveend + 600ms debounce
  │
  ├─ Phase 1 → POST /api/shadows/from-features（當前 1 小時）
  │              ~300–600ms → 立刻顯示陰影
  │
  └─ Phase 2 → POST /api/shadows/precompute（6–19 時全天）
                 cache hit → ~5ms，miss → 2–7s
                 完成後填入前端 cache → 拖曳時間軸瞬間回應
```

拖曳時間軸時，直接從前端 `cacheRef`（`Map<hour, FeatureCollection>`）讀取，不發 API 請求。

## 陰影幾何計算（Python）

後端 `shadow.py` 使用以下步驟：

1. **太陽位置**：pvlib NREL SPA → 方位角 (azimuth)、仰角 (altitude)
2. **座標轉換**：建物 footprint EPSG:4326 → 3857（公尺）
3. **陰影長度**：`height / tan(altitude)`，並加入 DEM 地形高差修正
4. **位移向量**：依太陽方位計算陰影多邊形位移
5. **陰影多邊形**：`convex_hull(building ∪ translated_building)`
6. **屋頂遮蔽**：STRtree 空間索引，找出被其他建物陰影覆蓋的屋頂區域
7. **回傳**：EPSG:3857 → 4326 GeoJSON

## 地形遮蔽

系統使用內政部 20m DEM，降采樣至 100m 後常駐 RAM：

- 每棟建物獨立查詢 DEM 地表高程
- 坡地陰影長度加入地形高差修正
- 前端可透過 `/api/dem/tile/{z}/{x}/{y}.png` 顯示 3D 地形

## 快取策略

| 快取 | 粒度 | 說明 |
|------|------|------|
| `shadow_cache` | 月份 × ~100m 格子 | 全天 6–19 時預計算結果（key v4） |
| `usable_fraction_cache` | footprint MD5 | 可用屋頂比例，180 天 TTL |

## Mapbox 深度測試修正

Mapbox `fill-extrusion` 在相同高度的多邊形會有 z-fighting。屋頂陰影圖層透過 `scalePoly(coords, 1.015)` 與 `height + 0.5` 稍微放大，避免互相遮蔽。
